01

Install

One binary, no dependencies.

curl -fsSL https://blackman99.github.io/keyroll/install.sh | sh

The script picks the archive for your OS and CPU from the latest release, checks it against the release’s checksums.txt, and puts keyroll in ~/.local/bin (set KEYROLL_BIN to change that). It is 49 lines; read it first.

go install github.com/Blackman99/keyroll/cmd/keyroll@latest

Or download keyroll_<os>_<arch>.tar.gz (zip on Windows) from Releases: macOS, Linux and Windows, amd64 and arm64.

02

Usage

Map, check, rotate, and CI.

keyroll (map)

Offline. Lists every key it finds, grouped by key, with each copy’s file, line, field name and class. Nothing is sent anywhere and no key is ever printed: you see sk-ant-…M1AA and the fingerprint #38bb1575 (first 8 hex characters of the key’s SHA-256).

$ keyroll keyroll 5 keys · 19 copies · 9 tools · offline, nothing sent ● Anthropic sk-ant-…M1AA #38bb1575 9 copies 3 live · 1 database · 5 leftovers live Claude Code ~/.claude.json:4 primaryApiKey live shell ~/.zshrc:6 ANTHROPIC_API_KEY live project .env ~/code/shop/.env:2 ANTHROPIC_API_KEY database OpenCode ~/.local/share/opencode/opencode.db → opencode auth login anthropic (then: opencode auth list) leftover OpenCode ~/.local/share/opencode/auth.json:4 anthropic.key legacy file: OpenCode v2 imported it into opencode.db and no longer reads it leftover shell history ~/.zsh_history:2 …

Classes: live (a tool reads it), leftover (nothing reads it, but it still works as a key: backups, legacy files, history, templates), database (SQLite app state keyroll never edits; it prints the command that replaces the key instead).

After the keys comes the credential store section: entries AI tools keep in the macOS Keychain, Windows Credential Manager or the Secret Service, found by name only. keyroll never reads their values, so they have no fingerprint; each shows what it holds and the step that replaces it by hand:

◇ credential store macOS Keychain 1 entry by name only: keyroll never reads these values by hand Claude Code "Claude Code" Anthropic API key · changed 2026-10-03 → run `claude`, /logout, then /login with your Console account

keyroll check [fingerprint…]

Sends each key to its own issuer, once, to a free read-only endpoint (table), at most 4 at a time with a 10 s limit each (--timeout). Prints ALIVE (the issuer accepts it), REJECTED (the issuer refuses it: revoked, deleted or mistyped), unknown or skipped per key, the spend limit where the issuer exposes it (OpenRouter), and which tools will fail because they still use a rejected key. Their 401s come from the issuer, not from a bug in your code. Exit code 1 when a rejected key is still configured somewhere live.

keyroll rotate <fingerprint>

Give the fingerprint (or its first 4+ characters, or the last 4 of the key). keyroll asks for the new key with echo off, or reads it from stdin if piped:

pbpaste | keyroll rotate 38bb1575 # macOS wl-paste | keyroll rotate 38bb1575 # Wayland keyroll rotate 38bb1575 --dry-run # show the plan, change nothing keyroll rotate 38bb1575 --ci you/agent-bot # also list that repo's Actions secrets
  1. The new key is cleaned of quotes and whitespace and refused if it is the same key, a login token, or another issuer’s key.
  2. Unless --offline, keyroll asks the issuer whether the new key works, and refuses one it rejects.
  3. It prints the plan: write for live copies, scrub for leftovers (the old key becomes [revoked-by-keyroll:38bb1575] and the new key is not added), by hand for databases, then the credential-store entries of the same issuer that may hold the key (listed by name; keyroll cannot see whether they do), and with --ci owner/name the GitHub Actions secrets whose names point at that issuer. It asks once (or --yes).
  4. Each file: originals copied to ~/.keyroll/backups/<time>-<fp>/, the old key’s bytes replaced, written to a temp file in the same folder with the original mode, fsynced, renamed over. Symlinks are written through to their target. A file that changed during the rotation is left untouched.
  5. keyroll scans again and prints how many places still hold the old key, then the by-hand steps (databases, credential-store entries, CI secrets), the issuer’s revoke page and its spend-limit page.
  6. The last line of every rotation asks the issuer about the old key: REFUSES means it is revoked; ACCEPTS means it is not, and copies keyroll cannot see (a hosted console, CI secrets, another machine) can still spend on it.

keyroll ci

Lists the GitHub Actions secrets whose names look like AI provider keys, through the GitHub CLI you are logged in with: repository, environment and organization secrets. GitHub never returns a secret’s value, so keyroll never sees one; it only runs gh secret list, gh repo list/view and GET requests through gh api, and refuses anything else.

keyroll ci # the GitHub repo of this folder keyroll ci --repo octo-demo/agent-bot # repeatable; owner/name or a github.com URL keyroll ci --owner acme-labs # every repo of a user or organization keyroll ci --all --json # every repo of your gh account
keyroll ci 7 of 11 secret names in 2 repos look like AI provider keys · names only, GitHub never returns values octo-demo/agent-bot repository ANTHROPIC_API_KEY Anthropic API key · updated 2026-10-03 → gh secret set ANTHROPIC_API_KEY --repo octo-demo/agent-bot env production OPENROUTER_API_KEY OpenRouter API key · updated 2026-10-12 → gh secret set OPENROUTER_API_KEY --env production --repo octo-demo/agent-bot … acme-labs organization secrets, usable by acme-labs/web org acme-labs PROD_ANTHROPIC_KEY probably Anthropic API key (the name mentions ANTHROPIC) · updated 2026-09-28 → an org admin updates it at https://github.com/organizations/acme-labs/settings/secrets/actions next keyroll rotate 38bb1575 --ci octo-demo/agent-bot --ci acme-labs/web rotating your Anthropic key lists these 2 secrets as by-hand steps
  • Names are matched against the variables each issuer documents (ANTHROPIC_API_KEY, GEMINI_API_KEY, HF_TOKEN, …), then against names that mention an issuer and end in KEY, TOKEN or SECRET, marked probably.
  • CLAUDE_CODE_OAUTH_TOKEN is a Claude Code login token (claude setup-token), not an API key: listed, never added to an API key’s rotation.
  • A secret has no fingerprint, so keyroll cannot tell which key it holds. The next lines pair each issuer with your local key of that issuer, and rotate --ci adds the secrets as by-hand steps that say if it holds this key.
  • Organization secrets get the settings page instead of gh secret set --org, which would reset which repositories can use the secret.
  • Needs read access to the repos (collaborator, or a token with the Secrets: read permission). Actions’ own GITHUB_TOKEN can never list secrets. Without gh, logged out or with a bad token it exits 3 and prints the command that fixes it; a repo it cannot read is reported and the others are still listed.
  • Not covered: Dependabot and Codespaces secrets, Actions variables, other CI providers. Not exposed over MCP, which stays offline.

credential_store is left out with --no-credstore; when the store could not be asked it carries skipped with the reason. holds is api key, api keys (several issuers in one entry), api key or login or login. rotate --dry-run --json puts the entries that may hold the key under the plan’s credential_store. No entry ever carries a value.

check --json adds a result per key: state, http, detail, endpoint, ms, and limit_usd / usage_usd / no_cap where the issuer reports them. Every JSON output is tested to contain no 8-character run of any key.

ci --json returns login, repos (name, secret_names, environments, error) and secrets: name, scope (repository, environment, organization), repo / environment / org, updated, provider, kind, match and manual. rotate --dry-run --json --ci … puts them under the plan’s ci_secrets. Names and dates only.

How keys are recognised

  • By issuer prefix where one exists: sk-ant-api03-, sk-ant-admin01-, sk-or-v1-, sk-proj-, sk-svcacct-, AIza, gsk_, xai-, hf_, csk-, fw_, pplx-.
  • Keys without a prefix (DeepSeek, Moonshot, Mistral, Z.ai, Together) only when the variable name or the JSON object around them names the issuer, e.g. DEEPSEEK_API_KEY= or a "deepseek" provider block.
  • Any other sk-… key is listed as unknown issuer and never sent anywhere.
  • Claude Code login tokens (sk-ant-oat…, sk-ant-ort…) are mapped but not checked or rotated: run claude /login.

Credential stores (names only)

Some tools keep the key in the OS credential store rather than a file. keyroll asks whether an entry with a known name exists and reads its public attributes (service, account, modification date), never the value: security find-generic-password -s NAME and find-internet-password -s URL without -w/-g on macOS, cmdkey /list on Windows (it cannot print passwords), and the Secret Service D-Bus method SearchItems on Linux (item paths only; keyroll never calls GetSecrets or secret-tool lookup/search, which print secrets). Any other command is refused in code and by a test. CI puts fake entries in the real Keychain, Credential Manager and GNOME Keyring and checks they are listed by name and the value never shows up.

The walk

From your home (or --root), keyroll reads .env, *.env, .env.local/.env.production and friends, .dev.vars, .envrc, opencode.json, .aider.conf.yml, .mcp.json, .claude/settings.local.json, .cursor/mcp.json, .vscode/mcp.json and .codex/config.toml as live; .env.example/.sample/.template, .env.* backups and editor Local History copies as leftover. It skips dependency folders, caches, VM images and agent transcript folders. A copy inside a git-tracked file is flagged, because rotating it locally does not remove it from history.

07

MCP

Read-only, fingerprints only.

claude mcp add keyroll -- keyroll mcp codex mcp add keyroll -- keyroll mcp

Or in any client’s JSON config: {"command": "keyroll", "args": ["mcp"]}. Tools:

  • key_map: every key (issuer, hint, fingerprint) with copy counts per class, plus credential-store entries by name. Optional provider.
  • key_copies: every file holding one key (by fingerprint), with class, field, line and the manual command for databases, plus the credential-store entries that may also hold it.

Both are annotated readOnlyHint, run offline and return no key material. There is deliberately no check or rotate tool: an agent should not be the one sending or replacing your keys.

08

FAQ

Why scrub leftovers instead of updating them?
A backup or an old auth.json holding the new key is one more copy to leak. Rotation should shrink the number of places a key lives, not keep it.
Why won’t it edit OpenCode’s database?
OpenCode v2 keeps credentials in SQLite and may be running. Writing to a live SQLite file from outside is how you corrupt it. opencode auth login <provider> is one command and does it properly.
Does it read my keychain?
It reads entry names, never values. It asks the Keychain, Credential Manager or Secret Service whether entries that Claude Code, Codex, Gemini CLI, Goose or Zed create exist, and lists them as by-hand steps. It never runs security … -w or -g and never decrypts anything. --no-credstore turns even the name lookup off.
Does it look inside agent chat transcripts?
No. A key pasted into a Claude Code or Codex chat lives in session logs; use spillscan for those.
Is a REJECTED key definitely revoked?
It means the issuer refused it just now (401 or its invalid-key answer). Issuers give the same answer for revoked, deleted and mistyped keys, so keyroll does not claim more than that. It never calls a key rejected on a 403, 429, 5xx or timeout; those show as unknown.
Can I run it in CI?
Map and check work anywhere (--root ., --json, exit code 1 on a rejected key that is still configured). Rotate is meant for your own machine.
Can it read my GitHub Actions secrets?
Only their names, because that is all GitHub gives anyone: secret values are write-only. keyroll ci uses those names to remind you which repos to update after a rotation. It never sets a secret; the replacement step is printed for you to run.
What does the fingerprint reveal?
32 bits of a SHA-256 of the key: enough to tell your keys apart in a list, useless for recovering the key.
Windows?
Yes: same binary, %APPDATA% and %USERPROFILE% paths, PowerShell profiles and history. Without a terminal for the hidden prompt, pipe the key in (Get-Clipboard | keyroll rotate …).
